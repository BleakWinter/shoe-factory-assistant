# 订包装业务规则

## 1. 页面与字段

订包装用于内部查看、核对和保存记录，不生成 Excel 或 PDF，也不要求沿用包装厂文件的版式。`包装.xlsx` 仅作为内容参考。

本次只实现订包装，使用独立的主表、明细表和接口。订大底、订中底、订鞋跟以后按鞋码数量设计，本次不扩展。

流程为：新建订包装 → 选择一个或多个订单的款号 → 核对汇总、展开修改规格 → 保存记录。同一款号只有一套样式，明细按“订单 ID＋规范化款号”汇总，同订单同款多行合并，不同订单分别保留。

汇总表显示订单号、开发款号、内盒规格、总双数、有箱数的装法、内盒类型、备注和款式图片。展开后显示完整的 14装～2装，并保留其他实际装法；可修改内盒规格、内盒类型和备注。箱数由装箱明细计算，不在订包装页面手改。

“内盒规格”默认来自开发款号配置中的 `boxSpec`，可对本次订包装覆盖。填写的是我们使用的内盒规格；包装厂自行查找相应外箱规格。配置中心新增“内盒类型”目录，每个内盒版本配置一个名称，可填写备注及启用/停用。款号在盒规配置中选择默认类型，订包装自动带出，也可仅修改本次记录的类型。内盒规格和启用中的内盒类型必须填写；不再填写胶袋、布袋。这里的修改只保存到本次记录，不修改开发款号配置。

## 2. 数据匹配与计算

系统将订单明细与 `order_packing_detail` 匹配：同一订单、款号一致（两边都有款号时），且装箱行的箱号范围完整落在该款来源明细的范围内。同订单同款的多行可组成连续范围，支持一个装箱行跨越这些来源行；箱号存在缺口时不跨越缺口匹配。缺少款号的旧装箱数据可按订单和箱号范围匹配。

同一装箱行被同订单同款的多个来源行关联时，只计算一次并保留全部来源订单明细 ID；被不同款号重复关联时，提示核对并阻止保存。

选择的是订单中的整款。预览、刷新、保存时，服务端补齐该订单该款当前全部来源明细，避免追加同款行后漏算；保存前装箱数据有变化时要求重新核对。

- 一行装箱明细可能代表多个箱子，按该行箱数计算，不能按行数统计箱数。
- “12装”等表示一个箱子装多少双鞋，不是鞋码。
- 单箱双数等于该行各鞋码数量之和。
- 优先使用该行正数 `cartonCount`；缺失或为 0 时按可解析的箱号范围计算，仍无法计算时按 1 箱兼容旧数据。负箱数或无效尺码数量需要核对。

```text
单箱双数 = Σ（该行各鞋码数量）
某装法箱数 = Σ（使用该装法的各行箱数）
总双数 = Σ（单箱双数 × 该行箱数）
总箱数 = Σ（该行箱数）
```

例如两行装箱明细分别为 `12装、10箱` 和 `10装、2箱`：

```text
12装：10箱
10装：2箱
总双数：12 × 10 + 10 × 2 = 140双
总箱数：10 + 2 = 12箱
```

1装、15装等实际装法单独显示并保存，不归入其他栏位。未匹配装箱明细、无效数量、同一装箱行被多个选中订单明细重复关联时，展示问题并阻止保存，需修正来源数据后刷新汇总。

保存前后端重新汇总，不接受客户端提供的数量作为结果。正式页面提交核对时的装法箱数和装箱明细 ID；若来源已变化，要求刷新汇总后重新核对。

## 3. 保存与历史记录

`packing_order_task` 保存编号、下单日期、订单号和款号汇总、明细条数、总双数、总箱数以及创建/更新时间。主表只服务订包装，不设下单类型字段。

`packing_order_task_item` 每条为一个订单与款号的组合，保存：

| 字段 | 含义 |
| --- | --- |
| `id`、`task_id`、`line_no` | 明细 ID、主记录 ID、显示顺序 |
| `order_id`、`order_no`、`development_no` | 来源订单及保存时的订单号、款号 |
| `box_spec` | 内盒规格 |
| `inner_box_type_id`、`inner_box_type_name` | 选择的内盒类型 ID 与保存时的版本名称 |
| `remark` | 订包装备注 |
| `quantity`、`carton_count` | 该款总双数、总箱数 |
| `packing_capacities_json` | 各装法箱数，例如 `{"12":10,"10":2}` |
| `source_detail_ids_json` | 合并的来源订单明细 ID 列表 |
| `source_packing_detail_ids_json` | 来源装箱明细 ID 列表 |
| `style_image_path` | 款式图片文件引用 |
| `created_at`、`updated_at` | 创建、更新时间 |

同一次记录中，`task_id＋order_id＋development_no` 唯一。规格与数量直接保存在专用字段中，作为当次下单的快照；包装明细不保存按鞋码订购的数量字段。

历史记录保留保存时的内盒类型名称，目录后续改名或停用不会改变历史记录；升级前未设置类型的记录显示“未设置”。历史记录读取快照，来源订单或装箱明细的修改、删除不会改变已保存的文字和数量。图片保留原文件路径引用，文件需继续保留在系统存储中。历史图片接口从快照路径读取，不依赖来源明细仍然存在。

启动新版本前，在实际使用的业务数据库依次执行 `sql/add_packing_order_task.sql`、`sql/add_inner_box_type.sql`。脚本可重复执行，不删除或覆盖已有记录；旧库中的胶袋、布袋列保留原数据，但新页面和接口不再使用。新建数据库的 `sql/print_table.sql` 也包含这两张表。订包装页面使用 `/api/packing-order-tasks`，不依赖通用配件下单表。

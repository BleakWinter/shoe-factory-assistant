# 鞋款报价

左侧“财务管理”包含“月度对账”和“价格配置”。“价格配置”分为“客户标价”和“报价管理”两个页签，分别显示“新建价格”和“新建报价”按钮。进入“报价管理”页签后点击“新建报价”，也可以从客户标价行点击“做报价”。

## 使用

1. 选择客户，填写款号、楦号、日期和颜色 / 材料。鞋图可直接上传 PNG/JPG（最大 10MB），或按客户和款号带入订单图。
2. 在一页内填写鞋面材料、包装与辅料、加工费。项目金额为用量 × 单价；用量、单价和加工费支持四位小数，行金额及合计保留完整计算精度。
3. 默认不计入大底、中底和鞋跟；勾选后必须补齐所计入项目的用量和单价。空值代表待填写，明确填写 0 代表零用量 / 零价。
4. 最终报价可向上取整元、四舍五入整元、保留两位小数，或手动调整。默认向上取整，与原报价单的处理方式一致。
5. “保存报价”允许保存不完整草稿；每次有修改的保存生成独立新版本。重复点击保存而没有修改时复用已保存版本。版本下拉可查看旧版，旧版内容另存时生成最新版本，原记录保留。
6. “复制为新款”带入项目、费用、图片和备注，清空款号，生成独立报价。已经选定客户 / 款号的报价不能在同一版本组中更换归属；更换时使用复制功能。
7. “采用为客户单价”要求客户、款号、日期和参与报价的项目完整，只允许采用最新版本。把报价单打印给客户签字后，在确认框上传一张签字报价单照片（PNG/JPG，最大 10 MB），核对当前价和新价，再确认采用。普通草稿的签字照片留空。新版与同组最近已归档签字照片的版本内容一致时，确认框允许沿用原照片路径，也可上传新照片。核对包括客户、款号、楦号、日期、颜色 / 材料、鞋图、报价明细、加工费、最终单价和打印版式。只改普通内部备注且打印版式相同时可沿用。已有签字照片的版本再次上传并确认会生成新版本，原版本保留原照片。出货查询和未确认的结算单使用新价，已确认的结算单使用当时的价格。
8. 点击“打印 / PDF”后选择“打印报价单”或“打印签字照片”。报价单包含当前页面内容，尚未保存时会显示草稿版本。签字照片读取当前所查看版本的归档原图，按 A4 纵向等比例排版。两种打印内容均可在浏览器打印中选择“另存为 PDF”。导出 Excel 会先保存当前修改，导出对应版本及计算公式。
9. 在报价列表跨页勾选多份报价后，点击“批量打印”，可选择“打印报价单”或“打印签字照片”。内容按勾选顺序打印，每张签字照片单独占一页。批量打印照片时会跳过未归档签字照片的报价，并提示跳过数量。

材料、辅料和底料区域按实际项目数扩展，原模板的 10 / 6 / 3 行作为最小行数。超出一张 A4 时，预览及打印 / PDF 自动分页，每页保留款号、客户和表头；Excel 导出包含全部明细与金额公式，长表按一页宽打印并重复表头。单份报价最多 200 个项目。

报价单中的“曾采用”只表示该版本过去被采用过；“当前客户单价”以 `customer_price_config` 实时读取的价格为准。

## 部署

备份实际业务数据库，确认已执行 `sql/add_multi_customer_ledger.sql`，再执行：

```text
sql/add_shoe_quotation.sql
```

已有报价库也需在更新后端前重新执行此脚本，以增加 `signed_image_key` 字段。脚本适用于 MySQL 8，可重复执行，保留现有报价、采用记录和客户标价。升级前已采用的报价可继续查看，照片显示为暂无。新库在基础建表及多客户升级脚本后执行此脚本。完成后更新并重启后端，构建并发布前端。

两张报价表及全部字段均带有中文数据库备注。已使用早期无备注脚本建表的数据库，执行 `sql/add_shoe_quotation_comments.sql` 补齐备注；该脚本保留字段类型、默认值和索引，不修改业务数据，可重复执行。

新增表：

- `shoe_quotation` 保存各报价版本，记录客户、款号、费用、金额、鞋图编号、采用时间及签字照片路径。`(version_group, version_no)` 唯一。
- `shoe_quotation_item`：该版本的材料与费用项目，保存项目内容、用量、单价及计算金额。

保存草稿仅记录报价与成本明细。采用价格前会校验并保存签字照片。客户 / 款号的 `customer_price_config`、报价采用时间和签字照片路径在同一数据库事务内更新。新版本保存与采用均锁定该版本组的最新记录。保存请求带 `expectedVersion`，版本落后时拒绝写入并保留页面修改，避免覆盖其他人的操作。

报价鞋图存储于配置的 `app.file-storage.root-path/quotation-images/年份/月份/UUID.png|jpg`，请将该目录纳入资料备份。带入的订单图在保存时复制为独立文件，旧版图片不会被新版本替换。上传尚未保存的图片也会占用该目录空间；当前版本不自动清理图片，以免误删历史引用。

签字照片存储于同一存储根目录下的 `quotation-signed-images/年份/月份/UUID.png|jpg`，请一并纳入资料备份。

## 接口

| 接口 | 用途 |
| --- | --- |
| `GET /api/quotations?customerId=&developmentNo=&page=1&size=20` | 最新报价列表，按客户、款号筛选 |
| `GET /api/quotations/{id}` | 指定版本及该组版本列表、当前客户价 |
| `POST /api/quotations` | 创建独立报价 V1，允许不完整草稿 |
| `POST /api/quotations/{id}/versions` | 保存新版本，必须带最新 `expectedVersion` |
| `POST /api/quotations/{id}/signed-photo-reuse` | 按当前报价内容核对可沿用的历史签字照片，返回来源版本 |
| `POST /api/quotations/{id}/adopt` | 采用最新、完整且尚无签字照片的版本。multipart 提供 `file` 上传新图，或提供 `reuseSignedPhotoFrom` 沿用匹配版本的照片 |
| `GET /api/quotations/{id}/signed-image` | 查看对应报价版本的客户签字照片 |
| `GET /api/quotations/reference?customerId=&developmentNo=` | 读取已有订单参考图、颜色 / 材料和当前价 |
| `POST /api/quotations/images` | multipart `file` 上传鞋图，返回 `imageKey/imageUrl` |
| `GET /api/quotations/images/{year}/{month}/{file}` | 读取归档鞋图 |
| `GET /api/quotations/{id}/excel` | 导出指定已保存版本，包含公式和图片 |

保存请求的项目类别为 `MATERIAL`、`FEE`、`OUTSOLE`；取整模式为 `CEIL`、`CENT`、`ROUND`。自动取价由后端重新计算，不信任前端传入的合计。手动最终价最多两位小数，最多 200 个报价项目。草稿中的未填金额为 `null`，不能用 0 代替。

## 验证

`mvn test` 中的 `QuotationTest` 检查原单示例 `24.595 + 1.5 + 5 + 48 = 79.095 → 80`、四位小数相乘、取整、空值 / 零值、底料计入、版本保留、过期保存、价格采用范围、图片格式 / 路径检查，以及导出公式的实际结果。前端使用 `npm run build` 检查类型及构建。

本功能提供系统内新建与编辑，不自动导入旧报价 Excel。此前提供的原报价单作为字段和计算规则参考，原文件保留。

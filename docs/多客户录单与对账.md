# 多客户录单与对账

## 使用方式

客户配置现为数据库持久化配置，不再是页面内的示例开关。初始客户包括：达为（Excel 上传识别）、宝翔和天兔子（手工录单）。新增客户目前使用手工录单；当前 Excel 模板仍专用于达为。

1. 在「客户配置」确认客户启用及出货／对账名称。
2. 在「订单」点击「新增手工订单」，填写客户、订单号、订单日期、款号、颜色／材料、双数；可添加多条明细，交货日期及备注可选，不填写单价。
3. 保存后订单立即参与订单及未出货统计。在订单详情点击「确认出货」，填写实际出货日期并勾选本次出货明细；每条明细按订单数量一次全部出货，不能填写部分数量。不同明细可在不同日期确认。
4. 在「数据统计」选择客户或全部客户，查看订单、已出货、未出货及货款。
5. 在「月度对账」选择客户和月份，核对该月实际确认的出货批次及金额。未确认出货的订单不会进入对账。
6. 在「财务管理 → 待定价款号」查看各出货月份尚未配置客户单价的记录；该入口与「月度对账」「价格配置」并列。月份和主款号汇总展示报价进度，展开后显示完整款号、鞋图、客户、报价状态、最近已报价格、版本、报价日期、出货日期及双数。已有报价显示「查看报价」，未填写最终价格的报价显示「继续报价」，没有报价记录才显示「做报价」。客户确认后，在已有报价中采用为客户单价，再刷新列表，历史缺价记录会同步移除。点击「出货明细」可查看原始订单号等记录。鞋图来自同客户、同完整款号最新有图的订单，点击可放大，没有图片显示「暂无图片」。

待定价款号在同一出货月份内按「客户＋完整款号」去重，多次出货只计 1 个款号，双数仍汇总全部出货记录。例如同一客户 10 月有两条 `JCD-162-15-03` 和一条 `JCD-205-1-34`，月份汇总为 2 个待定价款号、2 个主款号，进入月份后显示 162 有 1 个、205 有 1 个。展开后的完整款号也只展示一行，可点击「出货明细」查看该款全部原始记录。不同客户需要分别维护价格，同一款号在不同客户下分别计数；同款跨月出货也分别计入各月，首页的合计为各月去重数量之和。页面只展示已有实际出货记录且数量大于零的数据，未出货款号仍在数据统计的货款趋势中查看。

「待定价」表示当前未配置客户单价，包含三种报价状态：没有对应客户＋完整款号的报价记录为「未报价」；有已保存报价但所有版本的最终价格均未填写为「报价待完善」；已有最终报价、尚未转为当前客户单价为「已报价待客户确认」。状态与最近已报价格按全部报价日期查询，不受出货月份限制，零元最终报价也属于已报价。默认查看最新保存的报价；新版未完成时仍展示最近一个有最终价格的版本并标明「最新版待完善」，避免把已报过价的款号当作从未报价。若有历史采用记录、但当前客户单价已不存在，则显示「曾采用 · 当前未定价」。这里的待确认状态依据尚未采用客户单价判断，不会自动确认客户报价或改写单价；只有采用客户单价后才计入货款，零元客户单价也视为已配置。

同一客户的订单号不能重复；不同客户可使用相同订单号和款号。停用客户后禁止新增订单，但已有订单仍可继续确认出货、查看和对账。出货日期不能早于订单日期或晚于今天。

订单尚未出货时可编辑或增删明细；一旦已有出货记录，订单明细锁定，尚未出货的其他明细仍可确认出货，已出货的明细不可重复确认。补单请新建订单。目前未提供分批数量、出货撤销和已出货订单修改入口。

手工订单不需要 Excel、装箱单、配件下单或打印任务，且不会出现在这些达为专用的选择列表中。

## 数量与价格口径

- 工厂客户归属使用 `customer_id`，与达为 Excel 中的终端客人 `customer_name` 分开。
- 手工订单双数以明细数量为准；达为历史明细优先使用已有总双数，缺失时才按配码和箱数计算。
- 出货明细只关联来源订单明细，双数直接读取该明细全部订单双数，不新增实际出货数量字段。确认操作有提交编号和数据库行锁，重复提交不会重复记账；不同提交也不能再次确认已出货明细。
- 「价格配置」按客户＋款号维护，同款不同客户不会共用单价。
- 出货查询和结算草稿读取该客户款号的当前价格配置。确认结算单时保存当期单价、数量与补扣金额，之后按已保存的结算快照查看。
- 未知单价不当作零价：统计提示未定价双数，对账显示缺价明细且暂不计入金额。补齐价格配置后，缺价记录按配置计算；明确填写 0 则表示零价。
- 达为旧出货记录同样使用原订单明细全部数量和达为最新价格配置。
- 按实际出货日期归入月份。一条手工订单明细只允许确认一次，月度出货量以该月确认的明细数量汇总。

例如 A 款 100 双在 9 月出货、B 款 20 双在 10 月出货，则出货查询分别汇总 100 和 20 双。若 9 月账单按 A 款 12 元确认，之后改价到 20 元，9 月出货查询显示 2000 元，已确认的 9 月账单显示 1200 元。

## 部署顺序

升级现有库：

1. 备份业务数据库，确认升级连接的数据库名称。
2. 执行 `sql/add_multi_customer_ledger.sql`。脚本面向 MySQL 8，要求创建／删除临时存储过程及修改表的权限。DDL 会隐式提交，不能依赖事务回滚。
3. 更新后端、前端并重启服务。不要在未升级数据库时启动新后端。
4. 检查客户中文名称、达为历史统计和对账，再录入一笔手工订单验证。

新库：先执行 `sql/print_table.sql`，再执行 `sql/add_multi_customer_ledger.sql`。

升级脚本可重复执行：仅补缺失列和索引、初始化客户、迁移历史归属、复制达为旧款价，不清空订单或出货记录，不覆盖已维护的客户价格。旧 `shoe_style_config` 的盒规、净重、毛重配置保留；鞋价后续从 `customer_price_config` 维护。

本版只修改 `order_record`（客户、订单日期）和 `shipping_note_task`（客户、来源、提交编号）两张原有表，新增 `customer_config` 和 `customer_price_config`。`order_record_detail` 与 `shipping_note_task_item` 不需要新增字段。若已执行之前版本的升级脚本，额外列可先保留，新版程序不会使用它们，不必执行删列操作；若已存在真实的分批出货数据，应先核对再切换到全量确认版本。

## 新接口

- `GET /api/customer-configs`、`POST /api/customer-configs`、`PUT /api/customer-configs/{id}`：客户配置。
- `POST /api/manual-orders`、`GET /api/manual-orders/{id}`、`PUT /api/manual-orders/{id}`：手工录单和详情。
- `POST /api/manual-orders/{id}/shipments`：确认选中明细全部出货（包含 `requestId`、`shippingDate`、`detailIds`，不接收数量或单价）。
- `GET /api/orders`：增加可选 `customerId`、`sourceType` 条件，手工来源为 3，Excel 来源为 1。
- `GET /api/orders/statistics?customerId=...`：按工厂客户统计；省略客户则统计全部。
- `GET /api/price-configs?customerId=...`：客户款价；保存价格必须包含 `customerId`。
- `GET /api/monthly-reconciliations?month=2026-10&customerId=...`：月度对账，仍兼容原客户名称查询。
- `GET /api/monthly-reconciliations/unpriced-months?customerId=...`：待定价出货月份汇总，省略客户则汇总全部客户；返回月份、按客户＋完整款号去重的待定价款号数 `missingPriceCount`、主款号数及未计价双数，按月份倒序。`quotationCounts` 返回 `unquotedCount`（未报价）、`draftCount`（报价待完善）、`quotedCount`（已报价待确认），三项之和等于待定价款号数。
- `GET /api/monthly-reconciliations/unpriced-details?month=2026-10&customerId=...`：该月按主款号分组的待定价款号，月份及每个主款号均包含 `quotationCounts`；`groups[].styles` 为客户＋完整款号去重后的列表，每款保留鞋图地址 `imageUrl`（无图为 null）、双数合计和原始出货明细 `details`。`quotationStatus` 为 `NOT_QUOTED`、`DRAFT` 或 `QUOTED`，`latestQuotation` 指向最新保存的报价，`latestPricedQuotation` 指向最近有最终价格的报价版本，均包含报价 ID、版本、价格、报价日期、保存时间和历史采用时间；无对应记录为 null。省略客户则查询全部客户。

待定价款号功能复用现有订单、出货、报价版本和客户价格配置，无需新增数据库字段或执行迁移；更新前后端并重启即可。

## 本地回归

后端使用 Java 17 运行 `mvn test` 或 `mvn clean package`；前端运行 `npm run build`。新增单元测试覆盖达为每箱配码与总双数、按明细全量出货、跨月对账、改价重算历史及缺价提示。

`scripts/verify-multi-customer.mjs` 是会创建测试订单和客户的接口回归，**只能连接隔离测试库，不能对生产执行**。它固定访问本机 `127.0.0.1:18081`，测试日期为 2026 年 9／10 月。

准备一个独立 MySQL 8 测试库：先导入本次升级前的完整表结构，然后导入 `backend/src/test/resources/multi-customer-legacy.sql`，再执行升级脚本两次，验证兼容性与可重入性。该测试库达为应只有夹具中的 10 双订单、10 双出货和 250 元货款；不得混入真实业务数据。

后端使用这个独立数据库在 18081 端口启动后，运行 `node scripts/verify-multi-customer.mjs`。脚本覆盖手工录单、未出货编辑、跨客户同号同款、数字款号、按明细跨月确认、重复出货拦截、并发重复提交、改价后历史金额更新、缺价、客户停用和汇总相等。网页验证可通过 `SHOE_API_TARGET=http://localhost:18081 npm run dev -- --host 127.0.0.1 --port 5174` 使用独立后端。
